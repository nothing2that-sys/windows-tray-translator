# Quick Action Palette 수동 검증 절차서

## 0. 시작 전에

### 이 문서를 쓰는 이유

자동 판정이 가능한 항목은 `doc/QuickActionPalette_AutomatedVerification.md`로 옮겼다. **여기에 남은 것은 기계가 대신할 수 없는 항목뿐이다.**

- 사람이 눈으로 봐야 하는 것 (no-activate 창이 실제로 클릭되는가)
- 사람이 손으로 만들어야 하는 상태 (비밀번호 칸에 커서, 관리자 권한 앱, 네트워크 차단)
- 사람이 의미를 판단해야 하는 것 (요약이 말이 되는가)

### 준비물

| 항목 | 내용 |
|---|---|
| 빌드 | `artifacts\publish\windows-x64-self-contained\WindowsTrayTranslator.exe` (1.2.0) |
| 로그 위치 | `%LOCALAPPDATA%\WindowsTrayTranslator\logs\translator-<날짜>.log` |
| 설정 위치 | `%LOCALAPPDATA%\WindowsTrayTranslator\config\appsettings.json` |
| 필요 프로그램 | Chrome 또는 Edge, 메모장, Word 또는 VS Code, 보조 모니터(있으면) |

### 로그를 보는 방법

각 항목의 판정 근거는 **로그 한 줄**이다. 검증 중에는 로그를 실시간으로 띄워 두는 것이 가장 편하다.

```powershell
Get-Content "$env:LOCALAPPDATA\WindowsTrayTranslator\logs\translator-$(Get-Date -Format yyyy-MM-dd).log" -Encoding utf8 -Wait -Tail 5
```

이 창을 옆에 띄워 두고, 아래 절차를 수행하면서 나오는 줄을 그대로 복사해 매트릭스 비고에 붙이면 된다.

### 기록 규칙

- `PASS` / `FAIL` / `판정 불가` 만 사용한다
- **PASS에는 근거를 함께 적는다** — 로그 줄, 시각, 또는 관찰한 화면
- 코드를 읽어서 "그렇게 되어 있으니 맞다"는 것은 근거가 아니다. 그건 `판정 불가`다
- 재현이 안 되면 시도 횟수와 함께 `판정 불가`로 적는다

## 1. 보안 — 가장 먼저, 실패하면 release 중단

### 이미 확보된 증거

2026-09-16 로그에 **S1과 S4의 실제 차단 기록이 남아 있다.** 이 두 줄은 이번 설계의 핵심 안전장치가 실제로 동작했다는 증거다.

```text
14:50:52.527  [Information] 보호된 입력 여부를 확인했습니다. Result=Sensitive, ElapsedMs=1
14:50:52.528  [Warning] 보호된 입력 영역이 감지되어 클립보드 접근 없이 캡처를 중단했습니다. Process=chrome
                        ↑ S1 : 클립보드에 손도 대지 않고 차단

14:50:20.863  [Information] 보호된 입력 여부를 확인했습니다. Result=Safe, ElapsedMs=39      ← probe #1
14:50:20.888  [Information] 보호된 입력 여부를 확인했습니다. Result=Sensitive, ElapsedMs=19 ← probe #2
14:50:20.888  [Warning] 보호된 입력 영역이 감지되어 복사를 중단했습니다. Process=chrome, Attempt=1
                        ↑ S4 : 같은 Chrome 창 안에서 비밀번호 칸으로 옮겨간 순간을 잡아냄
```

**다만 각 1회씩이다.** 재현성을 확인하려면 아래를 반복한다.

---

### S1. 비밀번호 칸에서 `Alt+R` (반복 5회)

| | |
|---|---|
| 목적 | probe #1이 클립보드 접근 자체를 막는지 |
| 난이도 | 쉬움 |

1. Chrome에서 아무 로그인 페이지를 연다 (예: `https://accounts.google.com`)
2. **비밀번호 칸**을 클릭해 커서를 둔다. 글자를 몇 자 입력해도 된다
3. 입력한 글자를 드래그해서 선택한다
4. `Alt+R`
5. 로그 확인

**PASS 기준**

- 화면: `보호된 입력 영역에서는 사용할 수 없습니다.` 안내
- 로그: `Result=Sensitive` 다음 줄에 **`클립보드 접근 없이 캡처를 중단했습니다`**
- 로그에 `Gemini 요청을 완료했습니다` 가 **없어야 한다**

**FAIL 신호**: `Result=Safe` 가 나오거나, `선택 문자열을 캡처했습니다` 가 찍히는 경우

5회 중 몇 회가 차단됐는지 기록한다. → `_/5`

---

### S2. 클립보드가 보존되는지

| | |
|---|---|
| 목적 | 차단 시 기존 클립보드가 그대로인지 |
| 난이도 | 쉬움 |

1. 메모장에 `검증용문자열12345` 를 입력하고 `Ctrl+C`
2. S1을 수행한다
3. 메모장 빈 줄에서 `Ctrl+V`

**PASS 기준**: `검증용문자열12345` 가 그대로 붙여넣어진다

---

### S3~S6. 정상 입력란 + 창 내부 focus 이동 (앱별)

| 대상 | S번호 |
|---|---|
| Chrome | S3(정상) / S4(핵심) |
| Edge | S5 |
| Electron 앱 (VS Code, Slack, Antigravity 등) | S6 |

**S3 — 정상 동작 확인**

1. 로그인 페이지의 **아이디 칸**에 글자를 넣고 선택
2. `Alt+R`
3. 로그에 `Result=Safe` → 번역 팝업이 뜨면 PASS

**S4 — 핵심 항목. 같은 창 안에서 비밀번호 칸으로 이동**

이 항목이 이번 설계의 존재 이유다. `IsStillActive`는 같은 창 안의 focus 이동을 못 잡기 때문에 probe #2를 복사 직전에 넣었다.

1. **아이디 칸**에 글자를 넣고 드래그해서 선택한다
2. `Ctrl+Alt+A` 를 누른다
3. **누른 직후 곧바로 `Tab` 키를 눌러 비밀번호 칸으로 이동한다**
4. 로그를 본다

**PASS 기준**

```text
Result=Safe       ← probe #1 (아이디 칸일 때)
Result=Sensitive  ← probe #2 (비밀번호 칸으로 옮겨간 뒤)
보호된 입력 영역이 감지되어 복사를 중단했습니다 ... Attempt=1
```

**타이밍이 관건이다.** probe #1과 #2 사이가 수십 ms라 Tab이 늦으면 그냥 정상 캡처된다. 그 경우는 FAIL이 아니라 **재현 실패**다.

- 10회 시도해서 몇 회 재현됐는지 기록 → `재현 _/10, 재현 시 차단 _/_`
- **재현된 경우 전부 차단돼야 PASS.** 재현 자체가 0회면 `판정 불가`

**S5 / S6** — Edge와 Electron 앱에서 S3~S4를 반복한다. Electron은 UIA 구현이 다를 수 있어 별도 확인이 필요하다.

---

### S8. 관리자 권한 앱에 `Alt+T`

| | |
|---|---|
| 목적 | UIPI로 자동 입력이 차단되는지 |
| 난이도 | 보통 |

1. 메모장을 **관리자 권한으로** 실행한다 (`Win+R` → `notepad` → `Ctrl+Shift+Enter`)
2. 한국어 문장을 입력하고 선택
3. `Alt+T`

**PASS 기준**: `관리자 권한으로 실행된 프로그램에는 자동 입력할 수 없습니다...` 안내가 뜨고, 문장이 바뀌지 않는다

## 2. Quick Action Palette

### P1. 팔레트가 뜨는가

1. 메모장에 한국어 문장 2~3줄을 쓰고 선택
2. `Ctrl+Alt+A`

**PASS 기준**: 커서 근처에 `선택한 문장으로 실행할 작업` 제목과 `자연스럽게 다듬기` / `요약` / `닫기` 버튼이 뜬다

---

### P2. 팔레트 버튼 클릭 — **가장 중요한 항목**

| | |
|---|---|
| 목적 | `WS_EX_NOACTIVATE` 창의 버튼이 실제로 클릭되는지 |
| 왜 중요한가 | 이게 안 되면 기능 자체가 성립하지 않는다 |

1. P1 상태에서 `요약` 버튼을 **마우스로 클릭**한다
2. 결과 팝업이 뜨는지 본다
3. `자연스럽게 다듬기`로 반복한다

**PASS 기준**

- 클릭이 먹히고 `결과를 만들고 있습니다…` → 결과 팝업
- 로그: `Quick Action을 완료했습니다. Action=Summarize, ...`

**주의**: 지금까지 확인된 4건은 전부 `InputCharacters=5` 였다. **5자짜리 입력이 아니라 실제 문단으로 다시 확인한다.**

메모장 / Chrome textarea / Word / VS Code 각각에서 최소 1회씩 → P10 겸용

---

### P3. 원래 앱의 선택 영역

1. P1 상태에서 원래 앱의 선택 영역이 어떻게 보이는지 관찰한다

**기록만 한다.** 선택이 해제돼 보여도 **FAIL이 아니다** — 텍스트는 팔레트를 띄우기 전에 이미 캡처됐기 때문에 동작에는 영향이 없다. 다만 사용자가 혼란스러워하는지 여부는 UX 판단 재료다.

---

### P4. 8초 자동 닫힘

1. 팔레트를 띄우고 **마우스를 팔레트에서 멀리 치운다**
2. 스톱워치로 잰다

**PASS 기준**: 약 8초 뒤 자동으로 사라진다

---

### P5. hover 중 유지

1. 팔레트를 띄우고 **마우스 포인터를 팔레트 위에 올린 채로** 15초 이상 둔다

**PASS 기준**: 닫히지 않는다. 포인터를 치우면 그때부터 8초 뒤 닫힌다

---

### P6. 다른 창으로 전환 후 클릭

1. 메모장에서 문장 선택 → `Ctrl+Alt+A`
2. **`Alt+Tab`으로 다른 창(예: Chrome)으로 전환한다**
3. 팔레트가 화면에 그대로 있는 상태에서 `요약` 버튼을 클릭한다

**PASS 기준**

- 실행되지 않고 `선택한 창이 바뀌어 실행하지 않았습니다. 다시 선택해 주세요.` 풍선 안내
- 로그에 `Quick Action을 완료했습니다` 가 **없어야 한다**

---

### P7. 팔레트 표시 중 `Alt+R`

1. 팔레트를 띄운다
2. 닫지 말고 `Alt+R` 을 누른다

**PASS 기준**: 팔레트가 닫히고 읽기 번역이 진행된다

---

### P8. 다른 작업 중 팔레트 클릭 (busy)

| | |
|---|---|
| 난이도 | 어려움 — 타이밍 필요 |

1. 긴 문장(2,000자 이상)을 선택하고 `Alt+T` 를 눌러 번역을 시작한다
2. **응답을 기다리는 동안** 다른 문장을 선택하고 `Ctrl+Alt+A`

   → 이때는 `현재 번역 작업이 진행 중입니다.` 풍선이 뜨고 팔레트가 안 뜨는 것이 정상이다

3. 대신 이렇게 한다: 먼저 `Ctrl+Alt+A`로 팔레트를 띄워 둔다
4. 팔레트가 떠 있는 상태에서 `Alt+T` 를 눌러 긴 번역을 시작한다 (팔레트는 P7에 의해 닫힌다)

**P8은 현재 구조에서 재현이 까다롭다.** 재현되지 않으면 `판정 불가`로 적고, 대신 자동 테스트(`Admission_BusyGateKeepsSessionAndCapturedText`)가 로직을 보증한다는 점을 비고에 적는다.

---

### P9. 결과 팝업 즉시 닫기

1. 긴 문장으로 `요약` 을 실행한다
2. `결과를 만들고 있습니다…` 팝업이 뜨자마자 **`닫기`를 누른다**
3. 30초간 관찰한다

**PASS 기준**: 나중에 결과 팝업이 다시 뜨지 않는다

---

### P11 / P12. 모니터 위치

**계산 로직은 자동 테스트 70케이스로 이미 검증됐다.** 여기서는 실제 화면에 제대로 그려지는지만 본다.

1. 보조 모니터(특히 주 모니터 **왼쪽**이나 **위쪽**에 배치된 경우)에서 문장을 선택하고 `Ctrl+Alt+A`
2. 화면 가장자리(오른쪽 끝, 아래 끝)에서도 반복

**PASS 기준**: 팔레트가 화면 밖으로 잘리지 않는다

3. 배율이 다른 모니터(100% / 150% / 200%)가 있으면 각각에서 확인 — 글자가 깨지거나 버튼이 잘리지 않는지

보조 모니터가 없으면 `판정 불가 (보조 모니터 없음)` 으로 적는다.

---

### P13. 결과 복사

1. `요약` 실행 후 결과 팝업의 `복사` 버튼을 누른다
2. 메모장에 `Ctrl+V`

**PASS 기준**: 요약 결과가 그대로 붙여넣어진다

---

### P15. 히스토리에 기록되지 않는가

**이미 확인됐다** — 2026-09-16 히스토리 파일에 Quick Action 기록은 0건이었다. 재확인하려면:

1. 설정에서 `번역 히스토리 사용`을 켠다
2. `Alt+R` 로 번역 1회, `Ctrl+Alt+A` → `요약` 1회 실행
3. 트레이 → `번역 히스토리` 를 연다

**PASS 기준**: 번역만 보이고 요약은 없다

## 3. 기존 기능 회귀

probe가 들어가면서 기존 경로가 느려지거나 깨지지 않았는지 본다.

| # | 절차 | PASS 기준 |
|---|---|---|
| R1 | 한국어 문장 선택 → `Alt+R` | 번역 팝업이 뜬다 |
| R2 | 한국어 문장 선택 → `Alt+T` | 선택 영역이 번역문으로 바뀐다 |
| R4 | 설정에서 읽기 대상 언어를 `Select` → `Alt+R` | 언어 선택 팝업 → 고른 언어로 번역, 다음 번에 그 언어가 `(최근)`으로 표시 |
| R6 | 설정에서 보조 모델을 켜고 `Alt+R` → 팝업의 `보조 모델로 번역` | 두 결과가 나란히 표시 |
| R8 | `Alt+R` 을 10회 정도 반복하며 체감 | probe 도입 전과 비교해 눈에 띄게 느려지지 않았는가 |
| R10 | 히스토리 on/off 전환 후 각각 번역 | off일 때 기록되지 않는다 |

**R8 보조 근거**: 로그의 `보호된 입력 여부를 확인했습니다. ElapsedMs=` 값을 모아 본다. 2026-09-16 실측은 **1~39ms**로 예산 300ms에 한참 못 미쳤다. 100ms를 자주 넘으면 `SensitiveProbeTimeoutMs` 조정을 검토한다.

## 4. 단축키 — 자동 스크립트 사용 후 남는 것

H1/H2는 `scripts\Test-HotkeyConflict.ps1` 로 자동 판정한다(지시서 5절). 사람이 해야 하는 것은 아래 둘이다.

### H5. 설정 변경 즉시 적용

1. 트레이 → `설정 열기` → `번역` 탭
2. `Quick Action 단축키` 를 `Ctrl+Alt+Q` 로 바꾸고 저장
3. **재시작하지 않고** 바로 `Ctrl+Alt+Q` 를 눌러 본다

**PASS 기준**: 팔레트가 뜬다. 로그에 `전역 단축키를 등록했습니다 ... PaletteEnabled=True`

4. 다시 `Ctrl+Alt+A` 로 되돌린다

### H6. 트레이 토글

1. 트레이 아이콘 우클릭 → `번역 기능 활성화` **체크 해제**
2. `Alt+R`, `Alt+T`, `Ctrl+Alt+A` 를 각각 눌러 본다

**PASS 기준**: 셋 다 아무 반응이 없다 (확정된 동작이다)

3. 다시 체크해서 복구한다

## 5. 오류 및 네트워크

### E2. 네트워크 차단

1. Wi-Fi를 끄거나 네트워크 어댑터를 비활성화한다
2. 문장 선택 → `Ctrl+Alt+A` → `요약`

**PASS 기준**

- `네트워크 연결을 확인해 주세요.` 안내
- 앱이 죽지 않는다
- 네트워크를 복구하면 정상 동작한다

### E4. 팝업 제목

1. `요약` 실행 → 진행 중 팝업과 결과 팝업의 **제목**을 본다
2. `자연스럽게 다듬기` 로 반복

**PASS 기준**: 제목이 각각 `요약`, `자연스럽게 다듬기` 다. `번역 중` / `번역 완료` 가 보이면 FAIL

## 6. G2 — 의미·어조 유지 (사람만 판정 가능)

자동 하네스(지시서 4절)가 언어·라벨·marker·길이는 기계적으로 판정한다. **의미가 보존됐는지는 사람이 읽어야 한다.**

### 절차

1. 지시서 4절의 live 테스트를 먼저 실행한다
2. `artifacts\verification\gemini-contract-RewriteNatural-<시각>.md` 를 연다
3. 보고서의 길이비가 특이한 회차(최소·최대) 몇 개를 고른다
4. 같은 입력으로 앱에서 직접 `자연스럽게 다듬기` 를 실행해 결과를 읽는다

### 판정 기준

| 확인 | 질문 |
|---|---|
| 의미 | 원문에 없던 주장·수치·결론이 추가되지 않았는가 |
| 어조 | 존댓말/반말 수준이 원문과 같은가 |
| 누락 | 원문의 핵심 문장이 사라지지 않았는가 |
| 번역 아님 | 다른 언어로 바뀌지 않았는가 |

10개 샘플을 읽고 `_/10` 로 기록한다.

### 요약도 같은 방식으로

원문의 핵심이 요약에 들어갔는지, 원문에 없는 내용이 들어가지 않았는지 10개를 읽고 판정한다.

## 7. 결과 기록

수행한 항목은 `doc/QuickActionPalette_ManualVerification.md` 의 해당 행에 적는다.

```text
| S4 | ... | ... | PASS | 재현 6/10, 재현 시 차단 6/6. 로그 14:50:20 Result=Sensitive(19ms) |
| P2 | ... | ... | PASS | 메모장/Chrome/Word/VS Code 각 1회, 4자리 문단 입력으로 확인 |
| P11 | ... | ... | 판정 불가 | 보조 모니터 없음 |
```

### release 판정 규칙

- **1절(보안)에 FAIL이 하나라도 있으면 release 불가**
- **P2가 FAIL이면 Palette 기능 보류** — 팔레트를 기본 비활성으로 두거나 기능을 빼야 한다
- G5(marker 유출)가 0이 아니면 marker 거부 경로 재점검
- `판정 불가`가 남은 상태를 "검증 완료"로 적지 않는다. 남았으면 **조건부**다

## 8. 우선순위

시간이 없으면 이 순서로 한다.

```text
1순위  S1, S2, S4        - 실패하면 보안 문제. release 중단
2순위  P2                - 실패하면 기능 자체가 성립 안 함
3순위  R1, R2, R8        - 기존 사용자에게 가는 회귀
4순위  P6, P9, E4        - 새 기능의 안전장치
5순위  나머지
```

1~3순위만 끝나도 "조건부 release" 판단은 가능하다.
